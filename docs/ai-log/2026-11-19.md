## 변경안 미리보기 (AI 재배치 · 문장 추가 공통)

### planner 계획과 질문

- 지시: "planner로 변경안 미리보기 계획 세워줘". 자연어 요청이나 못 한 일 재배치를 바로 반영하지 않고, 전/후 변경안을 보여준 뒤 승인해야 반영
- planner가 확인한 현재 상태: QuickAdd의 1건 추가 미리보기, 스토어 액션(각각 set 한 번), 지난 일정 확인 팝업의 "재배치(준비 중)"는 있었고, 변경안 형식·전/후 화면·일괄 적용·재배치 해석은 없었음
- planner 질문 7개와 내 답

| # | 질문 | 내 답 |
| - | ---- | ----- |
| 1 | 변경안의 종류 | A. 추가와 미루기만. 삭제는 AI가 제안하지 않음 |
| 2 | 가짜 해석기를 어디까지 | 고도화 불필요. 문장 추가와 못 한 일 전체 재배치만 |
| 3 | 일정이 겹치면 | A. 허용하고 미리보기에 경고만 |
| 4 | 변경안이 떠 있는 동안 일정이 바뀌면 | 질문 취소. 구조상 팝업이 떠 있는 동안 바뀔 수 없음 |
| 5 | 화면 형태 | 팝업. 이미 팝업 패턴이 있어 질문이 불필요했음 |
| 6 | "저장 실패"의 정의 | 패스. 하나라도 실패하면 전부 실패가 지금 정책 |
| 7 | 지난 시간으로 재배치하면 | 질문 취소. 현실에서 그렇게 쓰는 사람이 없음 |

- 반성: 질문 4~7은 이미 정한 규칙이거나 현실적이지 않은 상황을 물은 것. planner는 decisions.md와 현재 구조로 답이 정해지는 건 질문에서 빼야 함 (planner.md 보완 후보)

### 확인 기준 (직접 써볼 것)

- 문장 입력 → "해석" → 캘린더는 그대로인 채 팝업에 전/후 표시
- 취소하면 안 바뀌고, 승인하면 반영
- 지난 일정 확인 팝업에서 "못 했어요" 저장 → "재배치" → 변경안 팝업 → 승인하면 원래 일정은 postponed, 새 일정 생성
- 팝업 타임라인에 미룬 기록이 보임
